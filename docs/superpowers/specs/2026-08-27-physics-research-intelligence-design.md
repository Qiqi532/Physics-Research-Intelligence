# 物理科研情报平台设计规格

## 1. 目标与非目标

目标是为个人研究学习提供一个每日可打开的 `Today Physics`：从权威与开放来源聚合物理学论文，使用 AI 形成可追溯的中文解读，并将最可能有价值的论文放入阅读队列。

第一版不做社交、多人协作、付费订阅、自动下载受限全文或替代文献管理器。系统不绕过校园网、VPN、登录或出版商访问控制。

## 2. 已确认的产品体验

### Today Physics 首页

- 今日统计：按全物理大类统计新论文、重点期刊文章及跨方向信号。
- 为你推荐：按兴趣、收藏、阅读/跳过反馈与新颖度排序；每项展示“为什么推荐”。
- 阅读队列：收藏、稍后读、完成状态与预估阅读时间。
- 兴趣设置：可选多个方向并设置权重；默认显示所有方向，交叉方向不可被静默过滤。

### 论文解读页

- 永久身份：标题、作者、期刊、日期、DOI、来源和出版社原文链接。
- AI 结构化输出：中文概述、研究问题、创新点、方法与证据、局限/待核验点、阅读路线。
- 证据规则：字段的每个关键结论标记为 `direct`、`inferred` 或 `uncertain`，且给出摘要句或开放全文段落引用。
- 原文访问：显示“可能需要校园网/VPN”；仅在用户点击时浏览器跳转出版社页面。

## 3. 合规与数据边界

允许持久化：DOI、公开元数据、作者、日期、期刊、分类、公开摘要/开放全文链接、来源、许可证、用户笔记与 AI 输出。

禁止持久化或传给模型：学校订阅获得的受限全文、登录 cookie、校园网凭据、个人 API 密钥。对于开放全文，只有许可证明确允许且来源连接器已启用时，才可将正文片段用于解读。

每条记录保存 `source_name`、`source_record_id`、`source_url`、`retrieved_at` 与 `license_url`，从而支持追溯与删除。

## 4. 推荐技术架构

采用模块化单体：一个 TypeScript/Next.js 应用提供网页与内部 API，一个独立 Node worker 执行定时采集及 AI 任务；两者共享 PostgreSQL 与类型定义。初版使用 Docker Compose 在个人电脑或单台云服务器运行。

建议技术栈：Next.js + TypeScript、PostgreSQL、Prisma、Redis + BullMQ、Zod、Vitest、Playwright、Docker Compose。任何模型厂商只通过服务端 Provider Adapter 调用。

```
公开来源 → 连接器 → 规范化/去重 → PostgreSQL → 任务队列
                                      ↓              ↓
                              Today Physics API ← AI 分类/解读
                                      ↓
                                   Web 页面 → 出版社原文链接
```

## 5. 领域模型

核心实体：

- `Paper`：DOI 主键、标准标题、期刊、发表日期、摘要、原文链接、可访问状态。
- `PaperSource`：一个 `Paper` 的一个来源快照；支持来源字段互补与审计。
- `PhysicsTag`：层级标签，如 `condensed-matter`、`quantum-materials`、`amo`、`particle-physics`；支持 `cross-disciplinary`。
- `PaperClassification`：标签、相关性、理由、模型与提示词版本。
- `PaperInterpretation`：结构化 AI 解读、证据引用、字段级置信度、状态和成本。
- `UserInterest`、`UserPaperState`：兴趣权重、收藏、阅读状态、点赞、跳过、笔记。
- `AiRun`：模型、provider、提示词版本、输入哈希、token、耗时、状态、错误码和成本估算。

## 6. 采集与去重

第一批连接器：Crossref（按 ISSN/日期的元数据）、OpenAlex（领域与开放访问补全）、arXiv（物理预印本）。随后按可用公开接口逐一增加 APS、IOP、Nature、Science 等重点期刊来源。

每个连接器独立运行并有分页游标、限流、指数退避、最后成功时间与失败记录。去重先按规范化 DOI；无 DOI 时仅将标题相似度、第一作者和日期共同满足阈值的记录标记为“候选重复”，不自动合并。来源失败只影响该来源，不阻塞日简报。

## 7. AI 与多 API 策略

定义统一 Provider Adapter：`classify`、`interpret`、`healthCheck`。适配 DeepSeek、OpenAI、Gemini、Qwen 等服务；调用参数、JSON 提取、错误映射、超时和速率限制在适配层处理。

### 两级任务

1. 批量分类：仅输入标题、摘要、期刊、日期。输出物理标签、交叉标签、相关性和简短理由。使用低成本模型。
2. 深度解读：只对高推荐分、收藏或手动触发论文执行。优先使用质量更高模型；只处理合规的摘要和开放内容。

深度解读必须输出 JSON，并遵守：不得虚构作者、数据、设备或指标；信息不足时填写 `uncertain`；每项创新点、证据和局限带引用；模型无法访问的全文必须明确说明。

使用主/备 provider：可配置任务级首选项；仅在网络、限流或服务错误时回退一次，不在“模型说不确定”时自动换模型。记录各 provider 的质量反馈与成本，之后再做路由优化。

## 8. 推荐排序

候选论文来自最近时间窗的分类结果。分数由以下可解释项加权：兴趣标签匹配、交叉方向新颖度、重点期刊权重、发布时间衰减、用户收藏/阅读反馈相似度与去重惩罚。每个推荐返回三条以内的可读理由，而非只返回分数。

第一版使用规则与权重，不使用黑盒个性化训练。用户可以在设置页调整兴趣，并在论文卡中“收藏”“不感兴趣”“稍后读”；反馈立即影响下次排序。

## 9. 可靠性、安全与可观测性

- API 密钥仅以部署环境变量提供，前端与日志必须脱敏。
- 任务幂等：同一 DOI、处理类型、模型和提示词版本组成幂等键。
- 每个外部调用设置连接/响应超时、有限重试和可见错误状态。
- 记录结构化日志与任务指标：成功率、延迟、来源新记录数、模型调用量、估算成本。
- 设置每日 API 成本预算；达到预算时只保留采集和分类，延迟深度解读。
- 每日备份 PostgreSQL；可按 DOI 删除来源快照和 AI 输出。

## 10. 验收标准

1. 手动执行采集后，至少能导入 Crossref、OpenAlex 与 arXiv 的样例物理论文，并能依据 DOI 去重。
2. 首页能展示今日总览、跨方向统计、可解释的个性推荐和阅读队列。
3. 论文页能显示完整来源链、原文跳转、结构化解读及字段置信度。
4. 无公开全文时，深度解读不会声称阅读过受限全文。
5. 断开任一来源或主模型时，其他来源/功能仍可用，错误可见且可重试。
6. 所有密钥不进入前端构建产物、版本控制或应用日志。
