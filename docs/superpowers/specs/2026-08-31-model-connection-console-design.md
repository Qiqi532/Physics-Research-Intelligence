# 模型连接管理台设计规格

**日期：** 2026-08-31
**状态：** 书面规格已由用户通过，进入 TDD 实施
**范围：** 单用户、本机优先的模型连接配置、测试与运行时路由

## 1. 背景

项目已经支持 OpenAI、DeepSeek、Gemini、Qwen、GLM、Kimi、混元和通用 OpenAI-compatible provider，并具有统一的分类、解读、健康检查、主备回退、成本估算与脱敏边界。目前这些 provider 只能通过进程环境变量配置，worker 启动时一次性构造 provider。对于个人试用，这使模型切换、多个账户比较和真实连通性测试过于繁琐。

本阶段增加页面内模型连接管理台。用户只需在本机页面填写 API Key，即可保存多个命名连接、测试连接和示例推理，并为分类与解读选择主备连接。现有 provider adapter 保持不变，环境变量配置继续作为兼容回退。

## 2. 已确认目标

- 提供 `/settings/models` 管理台页面。
- 同一供应商允许保存多个不同名称、Key、模型或接口地址的连接。
- API Key 在进入数据库前加密，页面和 API 永不回显原值。
- 保存或切换后，新任务立即读取新配置；运行中的批次继续使用自己的配置快照。
- 提供“检查连接”和“运行示例”两级测试。
- 分类与解读分别配置主连接和可选备用连接。
- 保留现有确定性、预算、幂等、事实/解读和 provider 回退规则。
- 默认只允许本机执行配置写入和真实模型测试。

## 3. 非目标

- 不增加多用户账号、组织权限、云端密钥托管或外部秘密管理 SaaS。
- 不在浏览器、URL、日志、遥测、Git 或论文记录中保存 API Key。
- 不自动迁移、读取或回显现有 `.env` 中的 Key。
- 不通过模型管理台修改提示词、物理标签或推荐算法。
- 不在自动测试中调用真实模型 API。
- 不允许从无认证的 LAN 页面执行密钥写入或付费测试。

## 4. 方案选择

采用“PostgreSQL 保存配置元数据与加密 Key，本机独立主密钥文件负责解密”的方案。

没有采用加密 JSON 文件，因为 Web 与 worker 并发读取、原子更新、备份恢复和未来容器共享都更复杂。没有采用页面写 `.env`，因为它是明文、只能自然表示每家一个连接，而且切换后通常需要重启。

## 5. 页面设计

用户选择了管理台布局：

- 左栏显示连接配置列表，支持搜索、供应商筛选、新建、复制、重命名和删除；复制只带入非敏感字段，必须重新填写 Key。
- 右栏显示当前连接的编辑表单、密钥状态和测试操作。
- 路由区域集中设置分类主/备连接和解读主/备连接。
- 桌面端使用双栏；窄屏按“连接列表、配置详情、任务路由”顺序堆叠，不创建独立移动交互。
- 页面主体为 Server Component；表单、测试和路由选择使用最小 Client Component。

连接表单包含自定义名称、供应商、模型名、API Key，以及接口地址、请求超时、输入和输出单价等折叠高级项。编辑时 Key 留空表示保留，填写表示轮换。

OpenAI、DeepSeek、Gemini、Qwen、GLM、Kimi 和混元使用现有 `aiProviderPresets` 填充默认接口和模型，允许用户显式覆盖。通用兼容连接必须填写接口地址和模型。非 HTTPS 地址仅允许本机 loopback，方便以后接入本地兼容服务。

## 6. 数据模型

新增一条只追加迁移，不修改历史迁移。

### `AiConnectionProfile`

- UUID 主键和当前固定为 `default` 的 `userId`。
- 在同一 `userId` 下唯一的 `name`。
- `provider`、`model`、`baseUrl`。
- 版本化密文字节、nonce 和加密版本；不保存明文、末四位或可逆提示。
- 输入/输出百万 Token 单价、请求超时、创建和更新时间。

### `AiRuntimeRouting`

- `userId` 单行主键。
- 分类主连接、分类备用连接、解读主连接、解读备用连接的可空外键。
- 更新时间用于诊断和快照标识。

路由写入使用事务。启用路由时两个主连接必须存在且可解密；备用连接可空，但不得与对应主连接属于同一供应商。被路由引用的连接不能删除。未启用路由时可以只保存和测试连接。

## 7. 密钥加密与恢复

- 使用 Node `crypto` 的 AES-256-GCM、随机 12 字节 nonce 和版本化 envelope。
- associated data 包含配置 UUID、供应商和加密版本，防止密文被移动到另一配置。
- 本机首次保存 Key 时自动生成 32 字节主密钥，使用独占创建。
- Windows 默认放在当前用户的 Local App Data 私有应用目录；Unix 默认放在当前用户数据目录并使用 `0600`。部署时可通过 `AI_SETTINGS_MASTER_KEY_FILE` 指向 Web 与 worker 共同挂载的文件。
- 主密钥、路径内容和解密错误细节不得进入响应或日志。
- 数据库备份只包含密文。完整恢复必须同时恢复主密钥文件；丢失主密钥后只能重新填写各 API Key。
- 本阶段支持页面轮换 provider API Key；主密钥轮换只写入运维步骤，不提供容易误操作的页面按钮。

## 8. 内部 API

- `GET/POST /api/model-connections`
- `PATCH/DELETE /api/model-connections/[id]`
- `POST /api/model-connections/[id]/health`
- `POST /api/model-connections/[id]/sample`
- `GET/PUT /api/model-routing`

连接响应只包含 ID、名称、供应商、模型、接口地址、安全高级配置、`hasApiKey` 和时间戳。不得包含 API Key、密文、nonce、主密钥路径或上游响应正文。

所有请求使用 strict schema，并限制最大请求体 16 KiB、最多 50 个连接、名称 1–64 字符、模型名 1–128 字符、Key 最大 8 KiB、URL 最大 2,048 字符、超时 1,000–120,000 毫秒、单价 0–10,000 美元/百万 Token；拒绝未知字段、重复名称、越界数值、非 JSON 写入和非同源浏览器请求。

`start-web.mjs --lan` 显式设置 LAN 模式。LAN 模式下允许读取非敏感配置元数据，但拒绝新增、修改、删除、路由更新和真实模型测试；页面显示“请回到运行服务的电脑操作”。默认 localhost 绑定继续作为主要安全边界。

## 9. 两级测试

### 检查连接

- 复用 provider 的 `healthCheck`，不发送论文内容。
- 返回安全状态、供应商、模型和耗时。
- 它验证鉴权与 API 可达性；是否能完成指定模型推理由示例测试最终确认。

### 运行示例

- 使用项目自有的固定合成物理论文标题与摘要，不读取数据库论文或受限全文。
- 对同一连接执行一次分类和一次简短解读。
- 运行前明确提示可能产生费用并要求确认。
- 返回两个任务各自的结构化结果、Token、耗时和估算费用；允许其中一项失败而显示另一项结果。
- 这是显式人工费用，不占用每日自动解读预算，也不写入论文、分类或解读表。
- 日志只记录事件、配置 ID、供应商、模型、状态和稳定错误码，不记录测试输入、输出正文或密钥。

同一连接只允许一个测试并发执行；健康检查完成后冷却 5 秒，付费示例完成后冷却 60 秒，避免重复点击产生费用。限制是单机进程边界，符合当前个人部署范围。

## 10. 运行时热切换

新增窄接口 `RuntimeAiConfigResolver`，从仓储读取并解密当前路由，构造按任务隔离的连接快照，然后复用当前 provider adapter、router、成本和 job 边界。快照不能继续使用以供应商名为唯一键的 `AiServerConfig.providers`，否则“分类用 Kimi 配置 A、解读用 Kimi 配置 B”会互相覆盖；环境变量配置只在解析后转换成同一任务级快照类型。

- `createConfiguredDailyProcessor` 不再在 worker 启动时固定 provider。
- 每次 `process()` 开始时读取一次路由快照，并在整个批次内复用。
- 下一批次读取更新后的路由，满足“新任务立即生效、运行中任务不变”。
- 分类与解读可以同时选择同一供应商的不同命名连接；每项任务内部的备用连接仍必须属于不同供应商。
- 没有持久化路由时才使用现有环境变量 `config.AI`。
- 已存在但损坏、缺 Key 或无法解密的持久化路由必须安全失败，不得静默切换到环境变量或另一供应商。
- 环境变量 factory 和测试保持兼容，不强制现有用户迁移。

原有 AiRun/AiRunAttempt 继续记录实际供应商、模型、Token、费用和错误。切换配置不会删除或改写历史审计。

## 11. 错误与隐私

页面只显示稳定、安全的分类：未配置、Key 无效、模型不可用、限流、超时、上游 5xx、接口不可达、密钥存储不可用和配置被引用。上游响应正文、请求头、连接串和内部堆栈不进入客户端。

损坏密文、主密钥缺失和数据库错误不会使 Today Physics 整页不可用；只影响模型设置与需要 AI 的新任务。事实浏览、兴趣和阅读状态继续工作。

## 12. TDD 与测试边界

严格先红后绿：

1. 加密单元测试：往返、随机 nonce、错误 associated data、损坏密文、缺失主密钥、文件权限与原值不出现在序列化对象。
2. PostgreSQL 仓储测试：同供应商多命名连接、名称冲突、Key 轮换、路由事务、引用删除保护和 teardown。
3. API 测试：strict 字段、请求上限、同源/LAN 边界、Key 永不回显、稳定错误码、并发测试和冷却。
4. provider 测试：只使用 mock fetch；health 和 sample 不访问真实服务。
5. worker 测试：fake resolver 证明批次快照、下一批次热切换、持久化损坏安全失败和环境变量兼容回退。
6. Playwright：空状态、新建 Kimi/GLM 多配置、编辑留空保留 Key、Key 轮换、两级测试、主备保存、引用删除、错误状态、键盘与桌面/窄屏布局。

自动测试使用专用 PostgreSQL schema、临时主密钥目录、mock provider 和 mock queue。不得读取真实 `.env`、真实 Key、生产数据库或真实模型 API。

## 13. 验收标准

- 用户可在页面保存多个同供应商命名连接，并在不重启 Web/worker 的情况下切换后续任务路由。
- API Key 不出现在任何 API 响应、HTML、客户端状态、URL、日志、Git diff、数据库明文字段或测试产物中。
- 连接检查和示例测试都能显示清晰的成功、部分成功和失败状态。
- 自动任务沿用预算、幂等、主备回退和公开事实输入边界。
- localhost 可完整管理；LAN 只能读取非敏感元数据，不能写配置或发起真实测试。
- 完整单元、PostgreSQL、Playwright、Prisma、lint、typecheck 和生产构建通过。
- 实现完成后，用户只在本机页面输入一个真实 Key，完成人工连通与示例验证；Key 不通过对话传递。

## 14. 已知边界

- 当前应用仍无登录系统，因此模型管理不对公网开放。
- 单进程冷却不作为多实例生产限流方案；未来多用户或多实例部署时需迁移到 Redis/认证边界。
- 主密钥文件与数据库备份必须分别保管；只恢复其中一项不足以恢复 provider Key。
- 真实模型名称、价格和供应商策略可能变化，页面允许覆盖默认值，文档不承诺预设永久有效。
