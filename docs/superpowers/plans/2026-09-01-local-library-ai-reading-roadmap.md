# Local Library and AI Reading Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement one approved phase at a time. Steps use checkbox (`- [ ]`) syntax for tracking. Do not start Phase 10 or 11 before its design is reviewed.

**Goal:** Turn the current personal Today Physics deployment into a durable local paper library that automatically selects 10–15 papers at Shanghai midnight, retains ordinary records for 30 days, preserves favorites, and later supports grounded reading assistance and favorite-library RAG.

**Architecture:** Keep PostgreSQL as the source of truth, Redis/BullMQ as replaceable operational state, and the existing Next.js Web plus worker boundaries. Favorites are orthogonal to reading progress. Public metadata and abstracts remain the default model input; locally stored PDF text may be used only when the source license explicitly permits storage or the user manually imports a lawful personal copy.

**Tech Stack:** TypeScript, Next.js Server Components, Prisma/PostgreSQL, BullMQ/Redis, existing `@pri/ai` provider abstraction, Vitest, Playwright.

## Status and approved product boundary

- Status: approved roadmap; implementation has not started.
- Start point: latest `origin/main`; the model-console release and homepage regression are present at predecessor commit `35faeadec3e9f01b68131dc50db4dc771f31956b`.
- Ordinary daily papers: retain database facts, classifications and interpretations for 30 days from local ingestion time (`Paper.createdAt`).
- Favorite papers: retain facts, classifications, interpretations and lawful local assets until the user explicitly removes the favorite and they later become eligible for normal retention cleanup.
- Reading progress and favorite state are separate: a paper may be favorite while `SAVED`, `READING` or `COMPLETE`.
- Automatic PDF download is allowed only when an explicit source/license rule permits local storage. Missing or ambiguous licenses never count as permission.
- A user may manually import a lawful personal PDF. The application must not redistribute it or assume that it may be sent to a model.
- Restricted publisher full text is never harvested, cached automatically, or sent to an AI provider.
- Classification, interpretation, reading answers and RAG results must disclose their source basis and distinguish direct evidence, inference and uncertainty.

## Existing boundaries to reuse

- `Paper.createdAt` already records local ingestion time and is indexed with `id`.
- `UserPaperState` already stores reading status, feedback and note, but has no independent favorite flag.
- `apps/worker/src/scheduler.ts` already provides timezone-aware stable daily windows and BullMQ scheduler reconciliation.
- `apps/worker/src/daily-pipeline.ts` already runs ingestion, classification, interpretation and Today preparation in order.
- `packages/ai/src/prompts/classify.ts` and `packages/ai/src/prompts/interpret.ts` already provide versioned strict prompts.
- `data/review-corpus/pdfs/` is an ignored evaluation corpus, not the future personal library. Do not reuse or mix these lifecycles.
- Current provider adapters are completion-oriented; an embedding or conversational contract must be designed explicitly before RAG or reading chat implementation.

## Phase 9B: Lawful local PDF assets

This phase requires a short design review before implementation because it adds a filesystem trust boundary.

- Store PDFs under a new ignored personal-library directory, never under the tracked evaluation corpus.
- Add database asset metadata containing paper identity, provenance, license decision, SHA-256, byte size and local availability; never expose an absolute filesystem path through Web APIs.
- Automatic download must use an explicit allowlist of accepted open-license identifiers/URLs and bounded size/content-type checks. Redirects, HTML masquerading as PDF and checksum mismatch fail closed.
- The first manual-import boundary should be a local CLI with an explicit paper identifier and file path. Browser upload can be evaluated later after authentication and CSRF boundaries exist.
- Removing a favorite does not immediately delete the PDF; normal retention cleanup removes it only after the paper becomes expired and unprotected.
- Backups must document database plus asset-directory consistency and restoration verification.

## Phase 10: Grounded paper reading assistant

This phase starts only after a real provider profile passes the management console health and synthetic sample tests.

- Extend the AI contract with a reading-assistant request that accepts a bounded evidence bundle, not unrestricted filesystem or database access.
- Add versioned prompts for question answering, section summary, terminology explanation and claim verification.
- Every answer must provide evidence locators and disclose whether it used public abstract facts, an explicitly allowed local PDF, or both.
- Do not silently send manually imported or restricted text to an external provider; require a visible per-asset permission state.
- Add bounded context size, cancellation, provider fallback, cost accounting, stable errors and conversation deletion.
- Begin with one-paper sessions; cross-paper synthesis belongs to RAG, not the first chat release.

## Phase 11: Favorite-library RAG

This phase also requires a separate design review.

- Index only favorite papers and only text that is eligible for model use.
- Use deterministic chunking, stable chunk hashes, source locators and idempotent re-indexing.
- For the initial personal-scale release, prefer storing embeddings in PostgreSQL and performing bounded application-side similarity over the favorite corpus; this avoids a new service or PostgreSQL extension. Revisit pgvector only when measured corpus size or latency requires it.
- Add an embedding-provider capability separately from chat completion. A provider without embeddings must not be treated as embedding-compatible.
- Combine semantic candidates with deterministic metadata/tag filters, then require cited evidence in generated answers.
- Deleting a favorite, asset or paper must remove or invalidate its chunks and embeddings. Rebuilding the entire personal index must be safe and documented.
- Evaluate retrieval recall, citation correctness, unsupported-claim rate, latency and cost before enabling cross-paper answers by default.
