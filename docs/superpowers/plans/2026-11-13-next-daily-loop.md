# 下一阶段：让每日推荐成为可用的本地工具

日期：2026-11-13。状态：**A/B/C 已实施并完成联合验收；2026-11-14 完成收尾，本机任务已启用。** 实际结果见 [开发记录](../../changes/2026-11-13-research-daily-loop.md)。

## 已确认的约束

- 本地单用户部署，保留 Next.js/TypeScript/Prisma/PostgreSQL，Redis 不作为默认依赖。
- 时间以北京时间 12:15 为初始目标，通常每天 5–8 篇，兼顾主课题与相邻方向，允许不足。
- DeepSeek 为主要 API，之后可以补千问/Kimi。暂不开发金额预算或费用看板，保留超时、重试、输出与候选数量边界。
- 公开标题/摘要可发送云端；PDF、笔记及其片段/派生总结默认留在本机。
- 不把人工逐篇验证作为前置条件；自动检查与模型共识不能充当学术真实性认证。
- 初始资料为 `D:\资料\毕设\文献`。已有盘点为 20 个 PDF，混有 SI、报告、本地稿，后续导入需区分角色。

Docker 已由用户修复，本轮已验证 PostgreSQL 健康；开发使用独立临时测试库，个人数据库迁移前完成备份和恢复核对。

## 为什么下一步先做日报

当前已能分别启动 Web 和一次性任务，但候选仍偏广泛物理分类，Today 也不是固定日报。直接加入聊天框或向量库，不能解决“每天到底有什么值得看、是否重复、失败后怎么办”。

建议下一阶段先交付**紧贴课题、固定名单、可恢复的每日推荐闭环**。之后再用同一文献身份与来源体系接入全文检索和摘要 RAG，减少两套流程。

## A. 课题画像与定向采集

交付：一份可编辑、可解释的研究画像，约 5–10 篇公开种子文献，主方向和相邻方向权重；不做复杂管理界面。

- 主线初值：二维/混维光电器件、栅控光响应、类视网膜感知、感内计算、运动感知。
- 相邻初值：神经形态器件与系统、光谱计算、CFET/垂直集成。已有库不等于全是偏好正例或已经读完。
- 先从已有导读在本地拟定线索，再以公开来源核对题录身份。不会把私人导读或其总结上传模型。
- 收窄现有 arXiv/OpenAlex 查询，Crossref 用于补全；先开合适的 1–2 个主来源，不追求来源数量。
- 期刊白名单由硬拒绝改为软加权；无期刊预印本可参加筛选，来源/版本明确标注。
- 摘要输入改成可配置的有界内容，不再固定只用前 200 字符；缺失/截断如实披露。
- 推荐理由说明对应主题/公开种子及摘要依据，禁止从摘要推断未见过的全文实验细节。

验收：固定样例能区分主线、相邻和不相关方向；无 DOI/无摘要/预印本不会被静默误处理。每篇保留来源与判断依据；不足 5 篇时少推，不填满配额。

## B. 固定日报与可恢复运行

交付：一次运行对应一份不可变报告；页面显示实际日报，失败和过期状态可见。

- 拟新增持久运行与日报数据结构，具体名称/字段在实施时设计；以本地日期、画像版本建立稳定运行身份。
- 保存实际论文 ID、顺序、推荐理由、依据和模型/Prompt/输入版本。报告显示集合与投递标记集合一致，短事务原子发布。
- 模型调用在事务外；阶段成功状态、失败原因和重试进度持久保存。
- 区分来源失败、候选为空、模型部分失败和完整成功。失败时保留上次成功日报并标注日期。
- 同一运行重复执行不重复投递，已完成阶段可复用；恢复不能依赖 Redis。
- 修正现有缓存仅看论文 ID 的缺口，纳入摘要内容、画像、Prompt 与模型版本；换画像/改摘要后重新判断。
- 来源水位只在对应处理成功后推进，并留适量重叠窗口接收迟到记录。
- 保持普通候选清理与未来用户资产分离；此阶段不导入或删除用户 PDF。

验收：同日重复运行、进程中断后恢复、多源部分失败、模型超时、发布写入失败均有回归；相同成功运行不重复调用和投递；Today 不再把历史候选重新排序后冒充日报。

## C. 午间自动任务

前提：A/B 的手动闭环通过，Docker 引擎已恢复，真实供应商连接由用户在本地配置。

- 提供 Windows 任务计划程序的安装、查看、禁用/移除脚本，使用项目绝对路径，覆盖中文与空格路径。
- 初始时间 12:15、业务时区 Asia/Shanghai；测试 Windows 系统时区不同的情况。
- 任务禁止并行，应用增加单实例保护和数据库稳定运行键，覆盖手动与自动同时启动。
- 按当前用户运行，不使用 SYSTEM，保证能访问 Docker Desktop 和同一主密钥。
- 开机/唤醒后补跑错过的任务；电脑关机期间无法生成日报，界面如实显示。
- 对长任务设置可配置的截止/恢复策略；不能把午间启动等同于全部模型请求都在闲时。
- 安装自动任务属于本阶段明确交付；已在手动闭环通过后注册并完成一次真实触发验收，具体状态见开发记录。

验收：模拟错过排程、手动/自动重叠和异常退出；恢复后不重复投递。真实试跑另外记录时间、来源覆盖和模型状态，不把 mock 结果宣传为长期稳定性。

## 质量与多模型边界

- 先做题录身份、输入 ID、结构化输出和摘录来源的确定性检查；引用存在与语义支持分开记录。
- 第二家 API 可用时再对少量入围摘要独立复核；只有一家时明确标注单模型，不把主备回退称为交叉验证。
- 争议结果可降级为观察项，不能通过多数表决补造事实。暂不全量三模型运行。
- 检索/相关性回归集和模型评分均标为代理指标，不能宣称真实推荐准确率；无需用户每天逐篇打分。
- 本地文件名、路径、笔记、稿件和私人上下文不会进入云端模型请求或云端评测。
